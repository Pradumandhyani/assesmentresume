# API specification and shared contracts

Steps 2–3 implement student authentication, dashboard, attempt lifecycle, drafts and final source snapshots. See [Step 2 routes](step-2.md#implemented-api-routes) and [Step 3 routes](step-3.md#implemented-api-routes). Operation descriptions distinguish implemented routes from reserved contracts.

`contracts/openapi.json` is the complete **OpenAPI 3.1** endpoint/response/error specification.
Its source is `scripts/build-openapi.mjs`. `contracts/generated/api.d.ts` is generated by
openapi-typescript and consumed by both browser apps and backend DTO aliases. Neither artifact
registers routes or implements business behavior. Do not infer route readiness from documentation.

API base: same-origin `/api/v1`. Production uses HTTPS, cookie authentication, exact Origin/CSRF
validation and role/resource policies. Request Content-Type is application/json. Runtime DTOs,
Nest guards and the central exception filter enforce the implemented Step 2 routes.
Use 128 KiB general request limits; configure a separately authorized, bounded 8 MiB administrative
version-upload route before implementing case upload. Never log request bodies. Request validation
error details name fields/rules only and never echo passwords, code or test payloads.

Successful JSON is `{ data: <endpoint-specific projection>, meta: { requestId, serverNow } }`.
All response UTC dates end in `Z`; accept unambiguous RFC3339 input offsets and normalize to UTC.
Decimal values are strings. Lists use `{ items, pageInfo: { nextCursor, hasMore } }` and opaque
cursor pagination with a hard 100-row limit. No endpoint returns unrestricted Prisma records.
Responses include `X-Request-Id` and `Cache-Control: private, no-store`.

Errors are `{ error: { code, message, requestId, details: [{ field, reason }], serverNow } }`.
Expected status mappings: 400 validation, 401 session, 403 role/CSRF, 404 absent/not owned,
409 state/revision/idempotency, 410 expired/finalized attempt, 422 invalid schedule/pool/version,
429 rate/concurrency limit, 503 dependency/backpressure, 500 sanitized unexpected failure.
429/503 carry `Retry-After`. Backend stack traces, SQL errors and judge diagnostics remain internal.
Reserved business routes return a sanitized 404 through the same central error filter.

All unsafe methods require `X-CSRF-Token`. Operations marked `key` also require a client-generated
`Idempotency-Key` persisted across retries. Start and finalization are naturally unique even if a
client chooses a new key; submission snapshots use durable key/hash uniqueness. See
[transactions](transactions.md) for conflict/replay semantics.

Nested IDs must be checked together with session ownership. Question version IDs in start/resume
are allocations, not permission for students to request arbitrary versions. Student profile/assessment
IDs are resolved from the authenticated identity. Explicit result release applies to SUBMIT/FINAL
feedback as well as the final result; public-only runs can show bounded public stdout/stderr earlier.

In a later step, serve the approved static specification or merge implemented route metadata with
Nest Swagger and fail CI on contract drift. Protect admin Swagger/interactive docs in production;
do not describe the unimplemented contract as a list of available routes.
